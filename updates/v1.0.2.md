# DoshyOS 1.0.2 — displays and graphics drivers

This release implements planning items #1 and #8.

## Updating an existing installation

Open **Settings → System updates → Check for updates**, select **Install update**,
and authenticate as an administrator. Restart after installation so the new display
restore service starts in your desktop session. Then choose your main screen under
**Settings → Display and monitors → Choose main screen**.

The update preserves personal files. Supported systems are DoshyOS on Debian 12
amd64 with the existing DoshyOS updater and baseline. A live USB needs working
**full persistence** (`/ union`); a RAM-only or home-only persistent live session
cannot install this system update. Systems without the updater need a combined
OS image first. No reformatting is needed for a supported in-place update.

## Main screen and saved layouts

- Choose which monitor contains the complete bottom bar, including Start, network,
  volume, tray and clock. New normal application windows open on that screen;
  dialogs stay associated with their application. Existing windows are not moved.
- Save monitor arrangement, main screen, resolution, refresh rate, rotation and
  disabled screens per user and per connected monitor set. Settings restore on
  login and when the same monitors reconnect.
- Choose side-by-side, swapped, mirrored or single-screen layouts. Fine-tune
  positions and rotation, or use the existing drag-and-drop ARandR editor. Its
  first Apply returns to the DoshyOS confirmation dialog.
- Keep changes within 20 seconds or the previous layout returns. An unavailable
  saved monitor setup is retained while an available display remains usable.

Profiles are in `~/.config/doshy/displays.json` (or `$XDG_CONFIG_HOME/doshy/`).
Openbox/Tint2 integration preserves other user settings and creates a
`.before-doshy-1.0.2` backup when it first adjusts an existing user configuration.
Custom system-file changes preserved by the OS updater may need review in the
updater's conflicts folder before the new startup behavior can take effect.

## Graphics drivers

Open **Settings → Graphics drivers** or find **Graphics drivers** under Applications.
The tool detects graphics cards and active drivers, checks signed Debian 12 package
sources, shows installed/candidate versions and the full proposed package changes,
and installs only after administrator authentication and confirmation.

- Intel/AMD: update Mesa and relevant firmware; full installations can also update
  the Debian kernel that supplies their graphics drivers.
- NVIDIA: update the open graphics stack, or use Debian's hardware-specific
  proprietary driver recommendation on a full installation with Secure Boot off.
  Unsupported or conflicting multi-card recommendations are refused.
- Persistent live USBs: userspace graphics and firmware packages can update.
  Proprietary NVIDIA and boot-kernel updates require a full installation because
  the live USB boots a fixed kernel/initramfs outside its writable overlay.
- Secure Boot: proprietary NVIDIA installation is blocked while enabled or
  unverifiable. The Recovery help explains signing/enrollment considerations;
  the tool never changes firmware settings or disables Secure Boot.
- No package removal, unattended reboot, arbitrary vendor installer, or automatic
  driver downgrade. An open-stack update does not switch an existing proprietary
  driver. Offline/package errors are reported and installation records are kept in
  `/var/lib/doshy-drivers/last-transaction.json` for recovery.

Use **Recovery help** before a driver change. On a full installation with a display
failure, GRUB's Advanced options can boot the previous kernel; Ctrl+Alt+F3 opens a
text login. DoshyOS file rollback is not a rollback of Debian driver packages.

## Verification

The release workflow runs updater, display-profile, driver-planning and real X11
smoke tests, plus shell regressions, before building the cumulative update archive.
Multi-monitor/GPU coverage uses simulated hardware; this does not replace testing
every physical graphics card, cable configuration, or persistent USB across reboot.

Ideas #2–#7 are not implemented in 1.0.2. Work on 1.0.3 begins separately.
